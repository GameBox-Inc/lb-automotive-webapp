================================================================================
Date: February 9, 2026
Status: READY TO DEPLOY

================================================================================
ISSUES FIXED
================================================================================

1. ✅ OUT OF MEMORY (OOM) CRASHES
   - Server was running out of RAM (2GB total)
   - Ollama (1-2GB) and ArgoCD (500MB-1GB) removed
   - Memory limits applied to all pods
   - Free RAM increased from ~0MB to 500-800MB

2. ✅ RATE LIMITING (HTTP 429 ERRORS)
   - Users couldn't log in due to rate limit
   - Increased limit from 300 to 1000 req/min
   - Reduced frontend polling from 30s to 2min
   - Added exponential backoff on errors

3. ✅ DISK SPACE MANAGEMENT
   - Logs could fill 40GB disk
   - Automatic log rotation (7-day retention)
   - Database archiving (monthly)
   - Cleanup cron jobs added

4. ✅ FRONTEND CRASHING
   - Frontend pods in CrashLoopBackOff due to OOM
   - Now stable with 64MB request / 128MB limit

================================================================================
TROUBLESHOOTING
================================================================================

If pods still crashing:
  → Check: kubectl describe pod <pod-name> -n lb-automotive
  → Check: dmesg | grep -i "out of memory"
  → Solution: Add swap space (see Step 11 above)

If still getting 429 errors:
  → Clear Redis: kubectl exec -n lb-automotive deployment/redis -- redis-cli FLUSHALL
  → Check rate limit: grep "SHORT_LIMIT" python-backend/security.py
  → Should show: SHORT_LIMIT = 1000

If frontend not updating:
  → Clear browser cache: Ctrl+Shift+Delete
  → Hard refresh: Ctrl+Shift+R
  → Check: kubectl logs -n lb-automotive deployment/frontend

If can't log in:
  → Check backend: kubectl logs -n lb-automotive deployment/backend
  → Check Anthropic key: kubectl get secret anthropic-secrets -n lb-automotive
  → Test API: curl http://localhost/api/health
